
- Server functions that must write client-protected columns (ratings, phone_verified_at, verification_status) set `app.trusted_write` locally and reset it before every return; guard triggers trust only that flag or non-client roles, so client writes can never bypass them.
- Format money, numbers and dates only via `src/lib/formatters.ts` (formatCurrency, formatNumber, formatDate, getDateFnsLocale); never hardcode `€`, `toFixed` for prices, `'pt-PT'` or `locale: pt` — so every screen follows the active language.
- Legal pages (Termos/Privacidade) render from i18n `legal.<doc>.sections` through `LegalDocument`; screen titles go through `useDocumentTitle`.
- Touch targets ≥44px come from the global invisible `::before` hit-area in `index.css` (mobile/tablet); add `.no-touch-target` only for elements that already use `::before` for visuals — so small controls keep their look.
- Icon-only buttons need `aria-label={t('a11y.*')}`; non-button clickables use `role="button" tabIndex={0} onKeyDown={onActivateKey}` from `src/lib/a11y.ts` — keyboard and screen-reader parity.
- Avatars for people/clinics render through `PersonAvatar` (`src/components/ui/person-avatar.tsx`) — one size scale, ring and name-derived initials colour.
- Use Tailwind scale tokens only: `text-2xs`…, `z-base|raised|sticky|dropdown|floating|overlay|modal|notification|toast|celebration`; no arbitrary `text-[Npx]`/`z-[N]` — consistency.
- On-screen decimals use `formatDecimal1`; money always `formatCurrency` (whole amounts without cents, otherwise 2 decimals).
- Blue text uses `--primary-text` via `.text-primary` (contrast AA); `--primary` stays for fills.
- Other users' names come from `professional_public_profiles` (view without phone/email/birth date) via `src/data/displayNames.ts`; full `profiles` rows of professionals are readable only by themselves and their clinic owner.
- Seed records are flagged `is_seed` (profiles/patients/appointments; sign-up with `@seed.smilecheck.app` is refused); only `refresh_seed_appointments()` (daily cron) moves them, filtering by `is_seed`, keeping a −14/+14-day window in 4-week steps so weekdays (Sunday rule) are preserved.
- Landing sections without real content stay behind flags in `src/lib/landingFlags.ts`; never show invented numbers, testimonials or certifications.
- Images in `public/` ship as WebP with a small PNG fallback at ≤2× display size; `Logo` serves the WebP via `<picture>`.
- Demo free text (mock notes, triage answers, waiting-list observations) is authored in PT and localised via `demoText`/`localizeDemoObjects` (`src/lib/demoText.ts`) from i18n `demoText.*` — so demo data follows the active language while real user text passes through untouched.
- Landing `data-reveal` animations never start above-the-fold content at opacity 0 and jump to the end after 1.5 s; `data-reveal="words"` elements need `key={i18n.language}` — so the hero is always readable and re-renders on language change.
- Plan prices, annual −15% and per-plan features come only from `src/lib/planRules.ts` (`PLAN_MONTHLY_PRICE`, `annualMonthlyPrice`, `PLAN_FEATURES`, `soon` flag) — landing and in-app plan screens can never drift.
- Public-schema functions are not executable by PUBLIC/anon (default privileges revoked); grant `authenticated` explicitly per function — anon only for helpers evaluated inside triggers (`is_untrusted_caller`).
- Dossier reads go through `can_read_dossier()` (active relationship) and are logged via `log_dossier_access`; fear: patient self-value in `patients.fear_level`, professional values insert-only in `fear_assessments`, never readable by the patient.
- Ad counters/timers and referral validation live server-side (`record_ad_view`, `referrals` + `try_validate_referral` triggers); the client never awards these points and never stores the counters locally.
- Agenda wall-clock times use the clinic's IANA `clinics.timezone` via `zonedParts` — never the viewer's or UTC.
- Brand fills with white text use `bg-primary-solid`; `--primary` stays the brand #2196F3.
- Screen entrance animations come only from `ScreenEnter` (`src/components/motion/ScreenEnter.tsx`), keyed by the screen so they run once per entry; Button's default variant self-marks `data-enter="button"` — no per-screen animation code.
- `profiles.plan` is written only by `sync_profile_plan()` (service_role, called from the `payments-webhook` edge function); subscription price ids are `<role>_<tier>_<monthly|yearly>` and must match `planRules.ts` (tested) — so the client can never grant itself a plan.
- Consent lives in `src/lib/consent.ts` (localStorage + `consent_preferences` when signed in); anything optional (stats, personalised ads) must check it — default is refused.
- The only service-worker registrar is `src/lib/pwa.ts` (refuses dev/preview/iframes); the worker caches the app shell and static assets only, never API/health data.
- Cheque eligibility is server-enforced (`trg_guard_clinic_cheques`, PT only, country derived from timezone); demo clinics use `src/lib/cheques.ts`.
- Reviews are only accepted after a `visto`/`concluida` appointment between both parties, one per appointment (`trg_guard_feedback_verified`).
- Payments act only on the server's active environment (`PAYMENTS_ACTIVE_ENV` secret + `payment_settings.active_env`, kept equal; switch both at go-live); client `environment`/`returnUrl` are never trusted (`_shared/paymentsGuard.ts`) — so test cards can never grant a real plan.
- Notification destinations come only from `src/lib/notificationTargets.ts` (type → `/app?tab=…` URL, mirrored server-side by `trg_normalize_notification_target`); sub-targets are handed to screens via `useDeepLink` (`src/lib/deepLink.ts`); unbuilt features use `SoonButton`/`openUnderConstruction()` (one shared pop-up, never a disabled control or "soon" label; tested) — so no click is ever a no-op.
- Account deletion goes through the `delete-account` edge function (logs `account_deletion_requests`, cancels Stripe subs, calls service-role `anonymize_account`, bans the auth user) — profiles are anonymised, never deleted, because appointments/dossier cascade from them and must be retained.
- "Download my data" is the `export_my_data()` RPC (own rows only, never `fear_assessments`).
- Professionals' levels, seals, plan badges and highlighted achievements render only for the owner (and, for dentists, their clinic); `professional_public_profiles.showcased_achievements` is always empty; search order is distance/price only (`getVisibilityBoost` is 0) — P2B neutrality pending the dental council's opinion.
- Consumer (patient) checkout requires `withdrawalWaiver`, enforced in `create-checkout` and stored via subscription metadata → `subscriptions.withdrawal_waiver_at`; VAT display comes from `planVatMode` in `planRules.ts`.
- Annual renewal reminders: daily cron `send_annual_renewal_reminders`, in-app.
- Terms acceptance is server-enforced: `require_terms_accepted` triggers (appointments, feedback, waiting_list, referrals, redemptions) and `create-checkout` check `has_accepted_terms()` against `current_terms_version()`; bump that SQL function and `TERMS_VERSION` together (tested) and `TermsGate` re-asks on next sign-in.
- `delete-account` cancels Stripe first (`process.ts`, tested); failures stay `pending` and the `retry-account-deletions` cron retries them.
- Real search only via `search_professionals` RPC (`searchSource.ts`: approved, public columns, neutral order); demo keeps mock — no rating/plan leaks.
- Clinic address/coords/`geocode_*` are written only by the `clinic-address` edge function (owner check, provider fallback, 1 req/s throttle, address cache); a trigger blocks client writes.
- Spoken languages: closed list in `spokenLanguages.ts` (mirrored server-side); weekdays via `weekdayLabels()`.
- Directory data only via `useDirectory()`: demo=mock, real=RLS.
- Clinical docs, rankings, jobs: writes only via RPCs/RLS (`issue_*`, `void_clinical_document`, `my_ranking`, `job_*` tables); public QR = anon `verify_document`; real screens are `Real*` beside untouched demo ones (`useDirectory().isDemo`).
- Social sign-ups pick role once via `choose_initial_role` (`role_pending`, trigger-guarded) — no client role changes.
